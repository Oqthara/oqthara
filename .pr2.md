Two documentation corrections to work merged in #76. No code changes.

## The function count was wrong

The changelog entry said the reference documentation "now covers 63 functions, up from 57". Both numbers were wrong. 63 was the document count in `docs/catalog.json` and 57 was that count before the change, so a count of documents was written down as a count of functions.

Measured against the generated reference, which is the artifact the sentence describes:

```
$ git show 55a29ec:docs/stdlib/reference.md | grep -c '| built-in |'
98
$ grep -c '| built-in |' docs/stdlib/reference.md
105
```

98 before, 105 after. The seven new functions are `arg_parse`, `log_debug`, `log_info`, `log_warn`, `log_error`, `log_level` and `log_enabled`.

## "Last verified" pointed at the wrong commit

The requirement matrix said `c7b7fa1` (the merge of PR #71) while its §17 row described logging and argument parsing that only exist from `d588130`. A verification date naming a commit older than the work it describes is the same failure mode: the document drifted from its subject.

Both were caught by checking a claim in a document against the artifact it described rather than against the document's own wording. No other count or SHA claims were found stale in ADR-0034, the specification or the matrix.
