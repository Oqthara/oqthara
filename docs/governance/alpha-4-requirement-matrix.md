# Alpha 4 requirement traceability matrix

Directive §4.3 makes this matrix a principal-agent responsibility: every Alpha 4 requirement in
the master execution directive must have a row, and every row must point at the evidence that
satisfies it.

This matrix is maintained by hand and describes **only what the repository actually contains**.
A row moves to `DONE` when the evidence exists on `main`; nothing is marked done because it was
planned, attempted, or believed to work. Where a requirement is partly met, the row says which
part is missing rather than rounding up.

Legend: `DONE` evidence merged and validated · `PARTIAL` some acceptance criteria unmet ·
`NOT STARTED` no implementation · `BLOCKED` waiting on something outside the work itself.

**Last verified:** `96dfdbd` (merge of PR #121), 2026-11-13.

Java's `PathMatcher` was deliberately not used, because its globstar requires at least one directory, so `**/*.oq` would not match a top-level `a.oq` and a program ported from the reference would silently skip files — the wrong-answer failure mode rather than an error. Recursion follows the pattern (only a `**` or a separator walks the tree), results are relative with `/` separators on every host, symbolic links are not followed, and a pattern matching more than a list may hold is an error rather than a truncation; `GlobTest` pins each rule, and every behaviour in the specification passage was probed against the built CLI, including the 100,000-entry cap. §17.2 and §17.3 gained descriptive statistics, identifiers and ordered search: `mean`, `median`, `variance`, `stdev`, `mode`, `percentile`; `uuid` and `is_uuid`; `heap_push`/`heap_pop` and `bisect_left`/`bisect_right` — 12 names, all needing no new type, no dependency and no lifetime rule, specified by [ADR-0041](../adr/0041-statistics-identifiers-and-ordered-search.md) and pinned by 35 tests. Three points are decided rather than left to chance: `variance`/`stdev` are the sample forms dividing by `n - 1` and refuse a single item rather than returning `0`; `mode` returns the smallest on a tie so the call is total where Python raises, and `percentile` interpolates between closest ranks rather than snapping to one; `is_uuid` refuses the braced, `urn:uuid:` and unhyphenated spellings that Java's `UUID.fromString` accepts, because a validator that takes strings other systems reject is worse than none. The cap is the point of the ADR: decompression counts the bytes it actually produces and stops at 16 MiB with a named error, because enforcing a cap by reading a length field from the input places the attack exactly where the defence should be — a hostile producer writes whatever length it likes. The obvious implementation, `readAllBytes()` on an `InflaterInputStream`, allocates the entire expansion before any cap can apply and therefore does not implement the cap at all; inflating in chunks and testing the running total after each is what makes the guarantee real. ## How a row is closed

A row may move to `DONE` only when all of the following hold on `main`:

1. The implementation is merged through a protected pull request with all required checks green.
2. The behaviour is pinned by a test that has been shown to fail without the change.
3. The specification and any ADR describe the behaviour as implemented, not as intended.
4. The conformance baseline has been re-measured rather than adjusted by hand.

Anything less is `PARTIAL`, and the row says what is missing.
