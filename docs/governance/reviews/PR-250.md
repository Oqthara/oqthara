## What this round was worth

This item exists because A7.5 was audited rather than trusted. Nothing in the tree was broken. Two
things were wrong in the *evidence*: a gate that accepted a placeholder as a version, and a residual
paragraph asserting Dependabot behaviour that is the opposite of what Dependabot does. Neither would
ever have failed a build.

### 1. The gate checked for a comment, not for a version (high)

`check_workflow` required a pinned `uses:` to have a trailing comment and emitted:

```
is pinned but the comment does not name the version, which makes the pin unreviewable
```

But the only condition was `if not comment:`. All three of these passed:

```yaml
- uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # not a version at all
- uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # TODO fix this later
- uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v
```

The comment is the thing that makes a pin reviewable, so a placeholder is worse than no comment: it
looks reviewed. It also has a second effect that is easy to miss. Dependabot's
`version_commenter.rb` rewrites a comment by finding the tag whose version string the comment ends
with; a comment containing no version is left alone while the SHA moves. The comment then describes
a version that is not the pinned one — a stale label on a moving pin.

### 2. The version comment claim was never executed (high)

A7.5's follow-up paragraph said "Dependabot will not update these pins by default", and R-008's
residual said Dependabot "does not rewrite `uses:` to a new SHA without configuration". Both are
false. The authority was a plain `github-actions` entry, which this repository already had, and the
proof is Dependabot's own pull request #16786 on `dependabot-core`:

```
-      - uses: ruby/setup-ruby@a0102e0972be65f351c307e2d64b9314a57c8073 # v1.324.0
+      - uses: ruby/setup-ruby@b3aaceaef7e0ee231b499e7b5f49c03fc1d32199 # v1.338.0
-        uses: github/codeql-action/init@b96794f015dfd88f77b49b1c93e0fa7110f94c63 # v4.38.0
+        uses: github/codeql-action/init@33d7b85da1a04171e211befe2c739303b9a4c066 # v4.39.3
```

`33d7b85d` is the commit `codeql.yml` pins here. The claim had been written from reading the option
list, where the behaviour is stated neither way — absence of a statement is not evidence of a
limitation.

### 3. The regression test asserted only what the gate asserted (medium)

`test_every_pinned_action_names_its_version` ended in `assertTrue(comment, ...)`, the same condition
as the gate. A test written to the same rule as the gate cannot catch the rule being wrong; it
certifies it. It now asserts a version-shaped comment independently.

### 4. The test's first replacement reused the gate's own pattern (medium)

The first fix asserted `checker.VERSION_COMMENT.search(comment)`, which is the gate agreeing with
itself again. Replaced with an independent pattern. That pattern then failed on `# v4` — correctly,
because major-only comments are legitimate here — so the assertion was corrected rather than the
gate loosened.

### 5. The read-only exemption's stated reason was wrong too (low)

The module docstring justified leaving `ci.yml`, `docker.yml` and `nightly.yml` on tags with "that is
where Dependabot's bump behaviour works without a config change". Tag bumps and SHA bumps both work
from a plain entry, so that sentence explained nothing. Rewritten to the actual reason: a tag is
acceptable where the job cannot publish or sign, because the cost of a repointed ref is bounded by
the permissions the job holds.

### 6. A correct review record was amended, visibly (low)

`PR-248.md` said the pins "will age" and that a `dependabot.yml` change was "the obvious next item".
Both are wrong facts. The record is a dated artefact, so the sentence is kept and the correction is
written beside it — a clean record is worth less than one that shows what was believed and why it
changed.

### 7. A pre-existing dangling reference was left alone (low)

R-002's residual ends `See R-008.`, which points at an unrelated risk and has done so since
`1e87f00`. It is a documentation defect, not part of this item's claim, and changing it here would
make the diff harder to review. Recorded, not fixed.

## Not claimed

- The strengthened rule does not verify that the version in the comment is the *right* version for
  that SHA. Doing so needs a network round trip to resolve the tag, which a CI gate should not
  depend on. The rule enforces that a version is named, which is what a reviewer needs to act on;
  checking that it is the correct one remains a review step.
- `github/codeql-action/{init,autobuild,analyze}` are three `uses:` lines and one Dependabot
  dependency. They move together, so a single stale comment among them is not an independent
  failure, but the gate checks each line because each line is what a reader sees.
- No `dependabot.yml` change is made. None is needed: the plain `github-actions` entry already
  present is the configuration that performs SHA bumps.

## Verdict

No blocking findings. Both defects were latent — no behaviour in the tree was wrong — and both are
now pinned by tests or by corrected text that names how the mistake was made.
