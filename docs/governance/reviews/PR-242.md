## What this round was worth

The change is four defect repairs and a release bump. Each repair was measured, mutation-verified
and recorded, and every gate was green when the review was requested. The review rejected it
anyway, and the reason is the one thing the gates cannot see.

The release commit, `0da89c4`, rewrote the risk register's `Last verified` paragraph to say that
all 29 entries had been re-read "programmatically" and that four of them had changed. Neither
sentence is true. An earlier commit in the same pull request, `f1ba127`, had said the honest thing:
that the boundary re-read had not been done and remained the first Alpha 7 item. The release commit
replaced a true sentence with a false one, and the false one shipped in the commit that declares
the release. The review found three entries whose numbers a re-read would have corrected — the
conformance corpus, the keyword count and the link count — which is exactly the evidence that the
re-read had not happened.

That is the finding this record exists for. The gates were not weak in a way a new assertion would
have caught: `check-risk-register.py` verifies exposure arithmetic, summary counts and ID
uniqueness, and a stale number inside a row body is invisible to all three. What failed was the
habit of asserting a verification instead of doing it, in the one commit nobody asked to review
again because every prior commit had been.

Two smaller falsifications came from the same round. The javadoc that justified four host-dependent
refusals quoted a measurement that read the opposite way from its own result, and the CHANGELOG's
own link table had no entry for the two most recent versions, so its version headings were plain
text.

One finding was not a documentation error but a real race: `Arithmetic.out()` was a lazy singleton
built by an unsynchronised check-then-act, so racing callers could each create their own
`PrintStream`. Two streams wrapping one `System.out` hold two locks, which would have silently
undone the atomicity that R-029's fix depends on. It was measured, repaired, and pinned.

## What is not claimed

The register's boundary re-read is still not done. Cadence rule 2 asks for all 29 entries to be
re-read at an Alpha boundary, and Alpha 6 is a boundary. Three entries were corrected here because
the review falsified them, which is not the same as having read the other 26. It remains the first
Alpha 7 item, and the register now says so instead of claiming otherwise.

`spawn`, `await`, `done` and `par_map` remain refused in compiled output. Removing them from
`Builtins.HOST_DEPENDENT` was measured at 218 of 223 compiled with 0 divergences, up from 214, but
enabling concurrency in compiled output is a capability change with its own review. The javadoc
records the measurement and the decision; the decision itself is deferred to Alpha 7, on the
record, rather than presented as out of scope.

This review was one round by one model that had also written the change. It rejected the change on
the first pass, which is the outcome that justifies the practice rather than one that vindicates
the model. The finding that mattered was not a subtle defect: it was a release commit asserting a
verification its author had declined to perform.
