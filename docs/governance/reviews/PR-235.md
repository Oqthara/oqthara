## On the review process itself

The first review agent was dispatched before the fix commit and wedged: it ran for 4351 seconds
across 176 tool calls without returning a turn, long past any reasonable bound. A tightly bounded
replacement was dispatched with zero permitted builds, no `git fetch`, `checkout` or worktree
operations, a cap of 25 tool calls and a read-only brief. It returned in about 555 seconds with
seven findings. The wedged agent then returned as well, with ten more. Both are recorded above.

The replacement's bounded brief turned out not to weaken the review: it found the HIGH finding,
which the unbounded agent also found independently. What the cap did was stop an agent from
rebuilding a Gradle tree to re-derive something it could read, which is the behaviour that made
the first attempt unbounded in the first place.

## What this review did not look at

The reviews examined the ordering change and the documents describing it. They did not re-audit
the construct-diagnostic work that PR #234 landed, which is covered by
`docs/governance/reviews/PR-234.md`, nor the `finally` reservation covered by
`docs/governance/reviews/PR-233.md`.

Two behaviours were found while measuring and deliberately left alone, because both predate this
change and neither is made worse by it. `NaN` cannot be used as a map key or set member: `m[nan] = 1`
stores and `m[nan]` then returns `nothing`, and `length(set([nan, nan]))` is 2. That is now
documented in `docs/spec/language.md` and pinned by the `NAN_AS_A_KEY` probe group, which scores
6 of 6 on both builds. And `nothing == nothing` is `true` while `nothing <= nothing` raises; the
ADR records it as an accepted inconsistency rather than silently claiming consistency.
