## What this round was worth

The value here is not the four corrections. It is that the report's own final section predicted the
failure mode and then committed it.

Item 10 already said, about R-031, that governance prose about the tree is not checked against the
tree. Item 9a then ended by repeating a claim about the tree without checking it, and the claim was
wrong — the gate it said did not exist has existed since the commit that fixed the thing the gate
checks. A report that charges the repository with unverified prose must verify its own.

The audit was cheap. Eight lines of `grep` and one deliberate edit found all four. The four had no
common author error; they had a common structural cause, which is that three of them were accurate
when written and decayed as later pull requests landed. A document this size will always decay that
way. What can be done about it is not "be more careful" — it is to check a claim before repeating it,
which is what turned this branch from a status-row edit into a correction.

ADR-0069's case is the sharpest. Had §5 been planned from Item 10 as written, the plan would have
been to write an ADR superseding ADR-0015 — a record that ADR-0069 had already replaced with one
saying the opposite. The cost of the stale sentence was a wasted decision, not just a wrong sentence.

  purchase on it, but saying "the build is green" here would be a claim this branch did not earn.

  next reader has to do what this branch did, which is check before repeating.
