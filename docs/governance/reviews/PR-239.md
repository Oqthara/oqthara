## Findings

Eight findings were consolidated from one round: no critical, no high, three medium, five low. All
eight are applied.

The review's most useful finding was not about the runner but about the tests. The eight new tests
called `codepath_failure` directly, so every one of them passed with the call site deleted from
`main()`: a correct rule that nothing invokes is indistinguishable from no rule, and the commit
that added the gate would have been guarded by tests that could not see its removal. The fix moves
the per-probe body into `check_probe()` and adds four tests that call `main()` with the three
subprocess calls stubbed. Deleting the `codepath_failure` line now fails two of them; gutting
`codepath_failure` itself fails six.

## What the round confirmed

- The codepath check cannot be skipped: every path through `check_probe` that reaches the jar run
  passes through it first, and the `continue`/`return` paths that bypass it are the ones that have
  already failed for another reason.
- `CODEPATH` matching `^codepath: .*$` is safe against probe output because `oq build` never
  executes the program, so probe output cannot appear in the build's stdout to be mistaken for the
  codepath line.
- `compiled_only` really was 17 of 18, and `FALLBACK`'s single entry matched the line `d1_sort_by`'s
  own build prints, verified by running `oq build --emit-ir` on it.
- `d2_class_instance` genuinely compiles: the IR shows `const class java.lang.String`,
  `call_value/1` and `method_call getClass/1` under
  `backend=classfile (self-contained writer, JDK 21)`.
- Loading `run.py` through `importlib.util` and the number of tests added were both as claimed.
- No divergence between the local sweep and what CI runs for this step.
