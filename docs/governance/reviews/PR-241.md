## What this round was worth

The change lowers three builtins and, while doing so, rewrites the javadoc next to the list it
removes them from. The rewrite said that `spawn`, `await`, `done` and `par_map` stay refused
because "a compiled jar has no scheduler". The review asked whether that could be falsified by
deleting the four names and building, and it could: all four cases compiled, because the scheduler
is `Stdlib.TaskRunner.EXECUTOR`, a static executor every jar links. A refusal whose stated reason
is false is not a decision, so the answer had to be found rather than restated.

The real reason is a bug. The interpreter emits a line with one `PrintStream.println`, holding the
stream lock across text and newline together. The compiled path calls `Arithmetic.print`, which
issues `out().print(text)` and then `out().print(newline)` — two lock acquisitions — so two
threads can interleave. Measured on a two-thread program: 18 of 40 compiled runs printed
`from taskfrom main`; 0 of 40 interpreter runs did. The lowering was reverted rather than shipped,
because shipping fused output to close a counter is the wrong trade and making compiled printing
atomic is a concurrency change, not an Alpha 6 one.

Two smaller things came from the same habit of trying to falsify rather than re-read. Three tests
looped over `FALLBACK`, which this branch empties, so they executed zero assertions and passed; the
review found them by asking what would fail if the check under them were deleted, and the answer
was nothing. And the accounting document quoted 222 where its own harness prints 223.

## What is not claimed

The concurrency divergence is not fixed. It is a real defect — compiled programs that print from
more than one thread can fuse two lines — and it is documented rather than repaired, because
`Arithmetic.print` acquiring the lock twice is a concurrency change with its own test strategy and
Alpha 6 is not the place for it. A reader should treat the compiled backend as safe for single-
threaded printing only.

`sort_by`'s per-comparison key evaluation is likewise still a separately pinned defect
(`ListSortTest`), pre-existing and unchanged here. Removing the three names from the host-dependent
set made `sort_by` compile; it did not make it correct.

This review was one round by one model. It found four false claims in documents that had been
written carefully, which is an argument for more rounds rather than for confidence in this one.
