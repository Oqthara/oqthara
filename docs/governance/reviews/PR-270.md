## What this round was worth

The interesting finding is not that two governance paragraphs were wrong. It is *how* they were
found: by trying to execute the ADR's own claims instead of re-reading them.

ADR-0070 was already written, already internally consistent, and already passing every gate in the
repository. Nothing in CI can tell a correct mechanism from a plausible one — both compile, both
render, both link-check. What separated them was running the program the ADR described:

```
$ java -jar oq-cli/build/libs/oq.jar run /tmp/p4.oq
<function <lambda>>      # print b.mapper
10                       # g = b.mapper; print g(5)
<function <lambda>>      # print b.mapper()
```

The first line is what the ADR's own words said could not happen. Reading the source then named the
site, and the ADR could cite `MethodResolverImpl.java:53` instead of asserting a behaviour.

The default-method error was worse, because it had already propagated. R-014 said `Proxy` for
months, and the ADR — written specifically to settle R-014 — inherited the error rather than
catching it. An ADR that records a limitation without reproducing it copies the limitation's
description along with it. The correction now appears in four places (ADR, register, brief, issue
#269), each saying what was wrong rather than quietly reading correctly.

The asymmetry in finding 1 is worth naming: `b.mapper` works and `b.mapper(5)` does not, and the
difference between those two spellings is invisible in the ADR's original phrasing, "reached by a
zero-argument accessor". A mechanism description that cannot distinguish the case that works from
the case that fails is not a description.
