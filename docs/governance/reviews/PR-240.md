## Findings

Five findings were consolidated from one round: no critical, no high, two medium, three low. All
five are applied.

The finding that mattered was about what the evidence actually proved. ADR-0065 retires A6.2 on
the premise that reflection is already reachable, and the first probe demonstrated that with
`String.trim`. But `trim` is a member the language reaches by name on any string, so the probe
showed only that `findVirtual` returns something — not that it reaches anything the allowlist
refuses. A second candidate, `getSuperclass`, turned out to be on `CLASS_SELF_DESCRIPTION`, so it is
not refused either. Both were found by asking "would this still pass if the claim were false?" and
in both cases the answer was yes.

The probe now names `getEnclosingClass`, which is in `CLASS_REFLECTION`: `c.getEnclosingClass()` is
refused, while `MethodHandles.lookup().findVirtual` plus `invokeWithArguments` reaches and calls
it. That program prints `nothing` on both backends and builds with `codepath: compiled bytecode`.

Two smaller findings came from the same habit. The spec block introduced as the probe file's
contents was an abridged program that differed from the file, so spec and probe could drift apart;
they are now compared programmatically rather than by eye. And the ADR's first draft implied the
reflective route is as convenient as an ordinary call, when in fact `MethodHandle.invoke` is
refused — it is signature-polymorphic — and `privateLookupIn` on a JDK class is blocked by the
module system. That is recorded now, because a record that overstates the convenience of the
alternative would be an argument against itself.
