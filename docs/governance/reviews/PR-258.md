## What this round was worth

The change is one classifier, its three call sites, four tests, and the governance record of what
was measured. It earns a pull request because of how the defect was found: by running the Swing
program §6 orders instead of reading whether one existed.

Alpha 7's report said, correctly, that the tree had no Swing coverage — and then drew a conclusion
the tree did not support: that §6's ordering was unsupportable. What the tree actually held was no
*evidence* either way. Running the program took four minutes and answered six questions the report
had listed as unanswerable, and in the process found a diagnostic that is wrong for every GUI
program on every headless machine. The report's own framing — "unverified in either direction" —
was the tell. A claim that something is unverified is a to-do, not a finding.

Finding 2 is the honest limit of finding 1. The classifier now names the right condition, which is
the part that makes a search work; it does not explain the condition, because explaining it per
type is a table the JDK would outgrow. Saying so in the record is better than writing three
special cases and implying the problem is solved.

## Not verified

- No test opens a visible window. Layout, painting, input dispatch, look-and-feel, and window
  lifecycle are untested and Direction 13 says so. A headless runner cannot cover them, so this is
  a permanent limit of the current CI, not a gap in this change.
- No conformance case covers D5, deliberately. Its trigger is a JVM with no display, so a case would
  pass or fail depending on the machine rather than on the bridge. `ImmutableRefusalTest` pins the
  classifier directly instead.
- The `.kilo/` agent roles were not exercised. This change is a runtime classifier; the §6 matrix it
  feeds was written by the implementing session, not delegated.
- `Main` was not rebased onto any later `main`. The branch was cut from `87f0bdc` and `main` did not
  move during the work.
