## What this round was worth

The change is a new CI gate plus the register re-read the gate was built to protect. All four
script gates were green, 252 tests passed, and the citation check had been mutation-tested twice
before the review was requested.

The review still found the gate dead.

`EXEMPT_HEADING` was the literal string `"## Citations that intentionally do not resolve"`, used
with `startswith`. The re-read itself added a `### The Alpha 7 boundary re-read` subsection, and
writing that heading demoted the exemption table from `##` to `###`. From that commit onward the
prefix matched no line in the document. Two things stopped working:

- the skip that protects the exemption table's own two columns never engaged;
- the reverse check — an exempted path that starts to exist must fail — was reachable only through
  that same `inside_exemptions` flag, so it was dead as well.

Nothing failed. The citation pass simply had nothing to complain about, `parse_exemptions` split on
the string independently and kept working, and the exit-code test was satisfied.

The tests could not catch it because each one that touched the section rebuilt the document from
`checker.EXEMPT_HEADING` itself. A test that shares a constant with the code under test asserts
that the two agree, and they did. That is the second time in this Alpha that mutation testing found
nothing while a shared assumption went unexamined; the first was the `Thread` test that passed on
JDK 21 and meant nothing on JDK 25.
