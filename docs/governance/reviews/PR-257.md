## What this round was worth

The change is two documents and a report annotation; nothing in the interpreter moved. It earns a
pull request because items 4 and 5 of the execution sequence are about to hand language-core work to
a role, and the two findings are both cases of the repository telling an agent something false about
its own instructions.

Finding 1 is the more embarrassing one. `docs/governance/README.md` already documents the mapping
carefully — it names all six `oq-hive-*` agents, says which `.kilo` roles each mirrors, and explains
why both directories coexist. The mapping was never lost. What was missing is that `AGENTS.md` —
the file an agent reads first, and the one this repository's operating instructions point at — never
mentioned the second directory at all. Documentation that exists in a file nobody opens first is,
for the purpose of directing work, documentation that does not exist.

Finding 2 is item 6's own warning, taken literally. The report said "the split has to be written
down, or a single role will be asked to do two roles' work under one name", and the split was not
written down. Writing it down took one section. The value is not the section; it is that a future
typing change now has an explicit fork in front of it instead of an implicit one.

  one agent-definition Markdown file. The build cannot observe the change.
- The new "Where your ownership stops" section has not been exercised by an actual typing change,
