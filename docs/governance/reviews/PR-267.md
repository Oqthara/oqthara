## Notes

The new job has not run, because nothing has been pushed. Everything else in this change was
executed rather than reasoned about, and the negative directions were checked in particular,
since a display gate that passes when no display exists is worse than no gate at all:

- Default probe run: `ok: 28 probes match their expectation` and `ok: 28 probes compared compiled
  bytecode against the interpreter`.
- `--under-display` on a real display: `ok: 29 probes match their expectation under the host's own
  display` and `ok: 29 probes compared compiled bytecode against the interpreter`.
- Forced headless with `JAVA_TOOL_OPTIONS=-Djava.awt.headless=true`: exit 1, with `c13_mapped`
  expected `['false', 'true', 'true']` and getting `HeadlessException`. The same run also shows
  why the flag is not used to simulate a headless host in the harness: `Picked up
  JAVA_TOOL_OPTIONS` is written to stdout and appears in every probe's output. That is why this
  change adds an Xvfb job rather than a second headless job with a different flag.
- `c13_mapped.oq` run directly with `-Djava.awt.headless=true`: exit 1, dying on the `JFrame`
  constructor. Run with a display: exit 0.
- `examples/swing.oq` through both backends, with and without a display: four runs, all exit 0.
- `ExamplesRunTest` was re-run with `--rerun-tasks`, because an up-to-date `./gradlew build`
  would not have executed it against the new example.

Two things this change does not claim. That Xvfb proves window-manager compositing — it maps the
window and reports it displayable, but runs no compositor, so that remains a desktop property.
And that `c13_mapped` proves anything about painting, layout or input dispatch: `c13_offscreen`
covers those without a display, and this probe is about realisation and disposal only.
