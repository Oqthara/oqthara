## What was examined

The claim under test is that re-running `scripts/check-ai-review.py` against `main` fails for
merged pull requests. It was checked by running the gate five times, once per record
(`GH_PR_NUMBER=224`, `225`, `226`, `227`, `228`), and confirming five distinct failures.

The explanation was checked by reading the ancestry rule in `scripts/check-ai-review.py`
around lines 395–450, which requires a cited SHA to be an ancestor of the branch, and by
confirming that the gate step in `.github/workflows/ci.yml` exits 0 when `GH_PR_NUMBER` is
empty. That is what makes the defect post-merge only rather than a live hole in enforcement.

Each cited SHA was then resolved in a `git clone` of `main` rather than in a working tree that
might have retained the objects. All five fail `git cat-file -t`. The first draft of this
paragraph had claimed only one of them was unresolvable; that claim was measured and was false.

`python3 -m unittest discover -s scripts/tests` reports 198 tests OK (1 skipped) and
`python3 scripts/check-docs-sync.py` exits 0 on this branch, so the added prose does not
disturb the documentation gates.
