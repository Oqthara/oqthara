## Notes

The brief's central claim — that the conversion works in both directions — was verified on the
interpreter and on a compiled jar, not inferred from `#122`'s commit message. The outbound
measurements were: `Function.identity()` value called with `()` (→ `9`), passed to `map` (→
`[1, 2, 3]`), passed to a user-defined `fun` parameter, returned from a user `fun`, stored in a
`data` field (the one failure), composed with `andThen` and re-passed to Java through
`Optional.map`, called from a `CompletableFuture` thread (→ `42`), and asked for a default method
(refused). The compiled backend was exercised for the two-value case and matched.

Two claims in the brief are marked as *not* measured rather than inferred: whether the same
Oqthara function compares equal to itself after crossing, and what happens when a `null` is handed
*to* a callback (the tests short-circuit inside `Optional` instead). Both are named as open in the
"Object identity" and "Null" paragraphs so that a later decision does not mistake silence for
settlement.

R-014 remains `Open` and the count is unchanged at 31 rows with 6 open, so the register gate's
arithmetic is untouched. The change corrects what a row says, not whether it is open, which is the
distinction the Alpha 6 closure made for `DONE` verdicts.
