## What this round was worth

The change is a gate that reads the report's numbers back from the tree. The finding that matters is
that its first version could not fail on the report's most important sentence, and it could not fail
there for a reason that looked like carefulness: it had a rule for "a sentence stating a change
contains a before figure and an after figure", and that rule swept up every sentence containing more
than one number. "Thirteen directions, 52 capability rows, D1–D5" is three unrelated counts and it
was exempted wholesale. Ten deliberate corruptions, three caught. That is the result that justified
building the two-sided suite rather than finishing the gate and shipping it.

The second structural finding is the table-row `continue`. It was written to stop markdown pipes being
read as prose, and it also stopped every table in the document from being checked — including the one
row where the probe coverage range is stated. A guard against a syntax artefact silently became a
guard against a document section, and nothing in the passing output distinguished the two.

Item 5 is the one worth carrying forward. Nothing in this change was aimed at
`alpha-7-security-baseline.md`; the gate was run against it as an over-reach check, and it came back
with three stale figures in a file whose thesis sentence says none can be stale.

Neither of the two obvious repairs was right. Rewriting the three numbers would have made the
document less true, because the table is a measurement of a specific commit and I cannot re-derive it
for *that* commit from today's tree. Deleting the table would have thrown away evidence. The defect
was never in the numbers — it was in the word "carries", which made a point-in-time measurement read
as a live one. Naming the measuring commit and saying which figures have moved keeps every sentence
in the file accurate at once, and costs one sentence to maintain. That is a smaller change than either
of the repairs I first considered, and it took an external reviewer's objection to see it: my first
draft of this record said I had deliberately left it broken.

Item 4 is the fourth occurrence of one defect in one report. PR-260, PR-261, PR-262 and PR-263 each
found a number that had quietly stopped being true, each fixed it by hand, and none of them built
anything that would notice the next one. This branch is the first that does, and it found a fifth
before it was finished.

## Not verified

- **The gate cannot see a claim shaped as "most targets" or "several probes".** It reads figures, not
  quantifiers. A sentence using a word instead of a number passes, and no test in this branch claims
  otherwise. Closing that would need a different mechanism — prose linting rather than arithmetic —
  and the report does not currently use that shape.
- **A claim-shaped sentence with no recognised noun is still caught, but a sentence that is merely
  *about* a number is not.** "There are 88 capability rows" is reported as unclassifiable; "the
  harness has grown" is reported as nothing. The boundary is "mentions a governance noun", and a
  sentence that implies a count without naming one is outside it.
- **The report is checked against the tree, not against its own history.** The gate proves today's
  figures agree with today's files. It cannot tell a number that was always right from one that was
  corrected in the same commit, and it has nothing to say about whether the *narrative* around a
  figure is still apt. Item 5's security-baseline drift was found by reading, not by this gate, and
  the three moved figures it names are disclosed rather than re-derived here: I did not re-run the
  threat model at `e43d384`, I read its committed summary table.
- **No branch-protection change accompanies this.** The gate fails the CI job, and whether that job is
  required is a repository setting this branch cannot read or set. A red gate is advisory until
  someone marks the context required, and R-031 in the risk register is exactly that scenario.
- **The mutation suite lives outside the repository.** It is a `/tmp` harness, recorded here as
  executed evidence rather than committed as a test, because its mutations are literal substrings of
  the report and would need rewriting every time the report's prose changes. The twenty committed
  tests cover the same classes through stable anchors; the mutation run is the broader sweep and is
