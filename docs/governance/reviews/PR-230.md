## What was examined

The claim under test is that `0.1.0-alpha.5` is a coherent release whose published notes do not
assert anything that was not measured. Every bullet in the new CHANGELOG section was checked
against the tagged source rather than against the implementer's memory of the change.

The several false claims were found by reading, not by running anything, which is why they are
recorded as findings rather than as test failures:

- `sort_by` is registered at `oq-stdlib/src/main/java/dev/oqthara/stdlib/Stdlib.java:247` and
  `git show v0.1.0-alpha.4:…/Stdlib.java | grep -c sort_by` reports 4, so it shipped before this
  release. The "one operation the matrix recorded as missing" sentence had no source in the
  matrix, which records §17 as `PARTIAL` against the Python index and says nothing about a
  keyed-sort gap.
- `git show v0.1.0-alpha.4:…/RuntimeCompatibility.java` shows the probe calling `list_sort` and
  `json_stringify`, and `grep -c` over the tagged `Stdlib.java` reports 0 for each name, so both
  were genuinely undefined and the failure the user reported was accurate.
- `scripts/verify-signature.sh:90–97` shows the regexp flag and the exact-identity override, which
  is what the corrected entry now describes.

Version agreement was measured rather than assumed, because a stale declaration would ship a binary that misreports its own version; this is a check that passed, not a finding: `python3 scripts/check-docs-sync.py` reports
"Main.VERSION, build.gradle.kts, the spec header, the LSP server and CHANGELOG agree on
0.1.0-alpha.5" and exits 0. That same run re-verifies 289 test-class citations, 107 test
methods, 18 quoted test counts and the 198 stdlib inventory citations, so the release does not
drift from the evidence the matrix depends on.

## What this review did not do

It did not review the `list_sort` implementation itself — that was PR #227, with its own record.
It did not independently verify the release workflow end to end, because the tag had not been
created at review time; finding 4 records that ordering explicitly. It did not check whether
`OQ_COSIGN_IDENTITY_EXACT` is exercised by CI, only that it exists.
