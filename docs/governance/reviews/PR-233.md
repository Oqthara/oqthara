## Escalations carried forward

The reviewer raised policy questions that are not defects in this pull request and are not
resolved by it. They are recorded here so the next change can pick them up:

1. **A pinned review target that keeps receiving commits makes "approved" ambiguous about which
   SHA ships.** HEAD moved twice during round two. The reviewer certified `36e707e` and verified
   the post-pin delta was documentation only. The recommended rule — a review names a SHA, and any
   later commit requires at least a delta re-check — is what round two did here, and should be
   written into `docs/governance/ai-review-policy.md`.
2. **Counts written into an ADR without a committed harness were wrong twice in a row.** Finding 10
   closes the instance; the policy fix is to require that any number in an ADR is generated by a
   committed script.
3. **`check-docs-sync.py` could not see citations outside `docs/`.** Finding 16 closes it for
   `conformance/**/*.oq`.
4. **Two hazards can invert a reviewer's conclusion.** `:oq-cli:jar` leaves `oq.jar` stale and
   `:oq-cli:standaloneJar` can report UP-TO-DATE, so probes must use `--rerun-tasks`; and
   `oq-lsp-0.1.0-alpha.5.jar` also contains `SignatureHelp`, so a mutant on a classpath is silently
   shadowed unless the mutant directory comes first. Both belong in the review policy.
