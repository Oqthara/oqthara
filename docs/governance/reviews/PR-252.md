## What this round was worth

This is a report, not a feature. Its value is decided by whether its claims are true, so the review
turned on re-deriving each one rather than on reading it back. Two of the report's own claims were
wrong when first written and are corrected below, which is the same class of defect the report
exists to find.

### 1. The report repeated the error it was reporting (high)

R-023 said the keyword count was stated "two ways across five documents". The first draft of the
report repeated "five documents". There are six statements: `docs/stdlib/reference.md`,
`CONTRIBUTING.md`, `docs/spec/design.md`, `AGENTS.md`, and two `oq-hive-*` agent files. The sixth is
`design.md`'s simplicity table, which the gate already checked — so the entry had missed the one copy
that was both correct and machine-verified while correctly naming the three that had drifted.

That is R-023's own thesis occurring inside the correction of R-023. Counting the statements
mechanically found it; no amount of re-reading the sentence would have.

### 2. R-021's stated reason had been false since 2026-11-11 (high)

The entry read "The workstream is unowned, per `alpha-4-workstream-assignment.md`." That file's row
9 says "Covered (ownership resolved 2026-11-11)" and carries a section with the same date in its
heading. The risk is real — `grep -c "rollback\|--update" scripts/install.sh` returns 0 and there is
no `oq update` — but a reader who followed the citation would have found it contradicted.

### 3. The first version of the new gate checked only the count (medium)

`test_a_stale_budget_is_rejected` failed on first run because the helper filtered problems for the
substring "keyword", and the budget message names a budget, not a keyword. The filter was the
defect: only one check is invoked, so every problem it returns is its own, and filtering could have
hidden a whole failure mode while the suite stayed green. The helper now returns all problems.

### 4. The new check had to be provable, not merely present (medium)

Two mutation passes were run. Reverting `AGENTS.md` to 20 produces "AGENTS.md claims 20 keywords but
the lexer defines 22". Rewording the orchestrator statement produces "does not state the keyword
budget and count in the expected form". Deleting the `agent_facing` block entirely fails 5 of 6
tests. The sixth, which asserts the real tree passes, correctly still passes.

### 5. A missing statement is a problem, not a skip (medium)

The gate reports a reworded or removed statement as a problem rather than falling silent. This is
the specific failure that let the drift live: the three agent files were never in the checked set, so
their stale counts were invisible rather than wrong. Any check whose coverage can shrink without a
failure reproduces that.

### 6. The report's type-system item is a blocker, and says so (low)

§5 of the directive orders optional typing and generics. ADR-0015 and
`type-system-decision-brief.md` both decide the opposite, and conformance cases 246 and 247 pin the
refusal with "typed fields are not supported" and "typed parameters are not supported". The report
records this as requiring a superseding ADR numbered 0068 and does not begin the work. Recording a
conflict is not resolving it, and the report says which one it did.

### 7. Two Open risks were verified without being repaired (low)

R-012, R-014, R-018, R-022 and R-027 were re-checked and left alone. None was closed on the strength
of its own text, and none was repaired beyond what its own evidence supported. R-018 in particular is
confirmed accurate, including its count of 8 targets and its ten unreached builtins, which is why it
becomes A7.8 rather than a correction.
