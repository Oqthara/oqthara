## What this round was worth

Item 8 is the weakest-specified entry in the Alpha 7 report: one line, no criteria, and an owner
citation that points at the typing section. The temptation is to invent a large observability
feature and call the item closed. Measuring first was the whole value of this round.

The measurement found that most of what "observability" suggests already exists. Elapsed time is
available through `timestamp()`; an earlier draft of the new report section asserted the opposite,
having tried `now()` — which returns text — and stopped there. That draft was wrong and was caught
before it was committed. `memory_mb()`, `type_of()`, spanned diagnostics and exit-status mapping all
work.

What did not exist was cheaper and more embarrassing: two of three file-taking subcommands could
not answer `--help`. The fix is a guard copied from the sibling that already had one, plus a
missing-file check. It would have been a small pull request because the evidence said the gap was small. Then the
audit that this record's own *Not verified* section had already predicted was needed found four
more commands with the same defect, so it is not small any more.

The worst of the four was `oq new`. Where the other three printed a wrong message, `oq new --help`
created a directory called `--help` in the working directory and announced `Created project
--help/`. A mistake that writes to disk is categorically worse than one that prints a bad sentence:
the user has to find and delete the artifact, and nothing told them it existed.

The reason five commands shared one defect is structural. `oq build` was fixed for this exact
mistake in an earlier change and left a comment explaining it, but a guard copied into one command
is not a rule that binds the others. Nothing in the repository enumerates the subcommands, so
nothing can assert that all of them behave alike. The parameterized test added here is the closest
available substitute — it names all eight — but it is a list a future author has to remember to
extend, which is precisely the failure mode that produced this finding.

## Not verified

- **No execution tracing was added**, so nothing here tests one. Whether a trace belongs on stderr,
  in a file, or as an Oqthara value is unrecorded, and this pull request deliberately does not decide
  it.
- **`oq run`'s new `-` rejection has no test for an argument that is a legitimate path starting with
  a hyphen.** Such a path was already unusable before this change, so nothing regressed, but the
  behaviour is now explicit and still untested.
- **`oq repl` and `oq java` were not covered.** `oq repl` is interactive and takes no file, and
  `oq java` and `oq runtime` manage the JVM, so none were expected to share the defect and none were
  changed. They were not exercised against `--help` either, so this is an expectation, not a
  measurement.
- **The list of subcommands in the new parameterized test is hand-maintained.** It names all eight
  file-taking commands as of this commit. A ninth command added later will not be checked unless
  somebody edits the test. There is no enumeration in the codebase to derive the list from, and
  creating one would be a larger change than this defect justifies.
- **A `-` rejection has no test for a legitimate path starting with a hyphen.** Such a path was
  already unusable before this change, so nothing regressed, but the behaviour is now explicit in
  four more commands and still untested.
