## Findings

Ten findings were consolidated from one round: zero critical, two high, four medium, four low. All ten
are applied.

The two high findings are the ones that mattered, and they share a cause: I wrote tests that asserted
on substrings of a file instead of on the behaviour I described in their docstrings. Finding 1 showed
that commenting out all four harness lines left every test passing, because `assertIn(path, body)` still
matched the path inside the comment — the step would exit 0 having run nothing, which is precisely the
silent green this PR exists to close. Finding 2 showed that the step reader scanned the whole file, so
moving the step into the `installers` job — which has no `matrix.java`, so the `if:` skips it — stayed
invisible. Both are fixed by parsing the workflow with PyYAML, which is already a CI dependency via the
docs scripts, and by looking the step up by name inside a named job.

## What the round confirmed

- `ci.yml` parses cleanly, and the new step sits in the `test` job on the `ubuntu-latest` / JDK 21 leg,
  after the step that builds `oq-cli/build/libs/oq.jar`. The backslash continuation inside the `run: |`
  literal block reaches the shell intact.
- Marking A6.4 `DONE` in the pull request that implements it is repository convention rather than a
  violation: PR #235 added its `DONE` numerics rows the same way, and the matrix header's "Last
  verified" language describes the post-merge state.
- The CHANGELOG's `grep -rn java-bridge-probes .github/` claim is past tense and was verified to exit 1
  on `origin/main` before this change.
- `--check` being parsed but never read in the three `probe-*.py` scripts is pre-existing and harmless,
  since those scripts check and exit non-zero regardless.
- The reviewer noted it exceeded the 25-call budget it was given. No file was modified by the review
  and no prohibited command was run.

## Excluded

A known non-defect in CI's existing vendor steps: CircleCI contexts report `conclusion: null` with
`state: SUCCESS`, so any summary that filters on `conclusion` alone falsely flags them. That predates
this change and no workflow file was edited to depend on it.
