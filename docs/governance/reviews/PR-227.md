## Findings

One round was run, and it was told to break the change rather than approve it. It found a
critical defect in the new code: a list containing `nothing` aborted the process with an
internal error that no program could catch. That defect was invisible to every test, because no
test had a `nothing` in its input. It also caught that the ADR's headline measurement had been
taken on one input and reported as the cost of the algorithm, and that the new ADR reused a
number another ADR already had. All nine findings are fixed in `36a145e`.

## What was examined

The reviewer read `git diff` and both untracked files, then went past reading: it ran programs
through the built jar to check each claim rather than trusting the comment that made it. It
reproduced the `nothing` crash, measured `sort_by`'s key count on five different orderings of
the same ten items, and verified the `oq build` claim in ADR-0060 by compiling both the plain
and keyed forms. It confirmed stability independently with interleaved equal keys, checked that
the one-argument path compares values rather than display strings, and swept the three existing
sorting builtins for behaviour change. On the test suite it specifically tested the suspicion
that `countingKey` was vacuous, and found it was not: the counter is monotonic, so the
once-per-item tests would fail under per-comparison evaluation, which mutation testing separately
confirmed by making three tests fail.

Two things it did not do, stated so the record is honest about coverage: it did not run
`./gradlew test`, reproducing the test semantics with equivalent programs instead, and it did
not exercise `oq runtime install` end to end. The second was then done outside the review — the
command was run on a real JDK 21 and installed the pinned runtime — so that claim in ADR-0060 is
supported by the implementer's run rather than by the reviewer's.
