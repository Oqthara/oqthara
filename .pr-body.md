## Logging

`log_debug`, `log_info`, `log_warn` and `log_error` write `LEVEL message` to the **error stream**, never the output stream, so redirecting stdout keeps it clean. Verified:

```
$ oq run l.oq 2>err.txt
out
$ cat err.txt
INFO  starting
```

The threshold is read from `OQ_LOG_LEVEL` once per process, defaults to `info`, ignores an unrecognised value rather than failing a working program, and `log_level(name)` changes it at run time. `log_enabled(level)` reports whether a level would be written. No timestamps: a program that prints a clock is not reproducible.

## arg_parse

Declarative rather than a parser the caller drives:

```oq
parsed = arg_parse(args(), ["verbose", "port:int", "name:text?"])
print parsed.flags        # ["verbose"]
print parsed.values.port  # 8080
print parsed.rest         # ["file.txt"]
```

- Types: `text`, `number`, `int`. A trailing `?` marks an option optional, and an absent optional is **absent from `values`**, not null.
- Errors name the offending token and list what was declared. All four paths verified: unknown option, missing value, wrong type (`--port abc` names `"abc"`), and missing required.
- `--` terminates option parsing; a lone `-` is positional; repeated flags dedupe; `a=b` is part of a text value rather than a split.

## One defect caught by regenerating the documentation

The four log functions were first registered in a loop over the level enum with a computed name. They worked, but `oq doc .` finds builtins by matching the literal string in the source, so the reference listed `log_level` and `log_enabled` while silently omitting the four that matter. Found by regenerating the reference after the tests were already green. They are now registered by literal name and the reference lists all six.
